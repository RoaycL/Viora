# 加载基线与来源缓存（第一批）

本批先保障数据可靠性并补上测量。继续观看、收藏、最近看过按服务器账号分别缓存；一台服务器故障不会把它的上次结果当作空列表写回。后续的逐来源呈现、请求取消/调度、数据库读写隔离另行实施。

## 更新规则

- 身份空间包含服务器 ID、服务类型、用户名、用户 ID 和排序后的服务器地址集合；密码、令牌刷新、线路选择和测速不改变身份。家长控制查询另有空间，限制后的列表不会覆盖不限分级的列表。
- 冷启动先读各来源的快照，后台刷新；后续主动刷新直接查询服务器。全部来源完成后合并显示，仍有最长 10 秒的列表等待预算。
- 完整成功才替换对应来源；完整的空列表表示该来源确实没有结果，可以清空。异常或不完整响应保留该来源旧数据和原刷新时间。界面提示暂未刷新，所有来源失败且没有快照时显示不可用提示。
- 继续观看最多 12 条、最近看过最多 60 条，是固定窗口。收藏分页读取完整集合，每页请求 200 条；偏移按原始响应条数推进，避免本地分级过滤改变偏移。没有总数时读取到空页。重复条目、总数变化、提前空页和超时均不能覆盖旧快照。
- 同一快照键串行临时文件写入后改名。来源所有权和清理代数阻止已失效请求写回。页面状态 family 使用身份空间，账号切换期间不会显示上一账号的 AsyncValue。

## 升级和账号变更

旧的全局 `resume/favorites/recently-played` 文件不导入：无法确认其所属账号。首次升级需要重新请求列表。旧文件不会继续参与读取。

索引新增 `index_accounts` 表。未带账号信息的旧索引首次绑定时清理并重新全量同步；以后只有变更、注销或移除账号的来源被清理。进行中的旧同步在写入前检查身份，不能填回已清理的数据。索引 JSON 同时保存 `OfficialRating`，使本地结果可以应用分级过滤。

播放信息/预热记录、本机播放时间也按账号隔离。旧的未区分账号的本机时间不再作为排序依据；服务器返回的播放时间仍然优先。收藏和已看状态仍以服务器为准，本批没有加入离线标记队列。

## 从现有日志观察加载

日志沿用设置页及局域网导出，不需要新的日志安装包。新增 `[load]` 行：

| `op` / `phase` | 含义 |
| --- | --- |
| 列表类型 / `cache` | 快照读取耗时、来源数、命中数 |
| 列表类型 / `first_data` | 应用取得首份可用列表数据的耗时；不代表已经完成绘制 |
| 列表类型 / `first_remote`、`complete` | 首个成功远端结果、全部来源完成耗时及失败/不完整数 |
| `search_local` / `complete` | 本地查询与可见性过滤耗时 |
| `search` / `local_ready`、`first_remote`、`complete` | 搜索各阶段总耗时和结果数 |
| `media_api` / `remote` | 每次实际服务器请求的耗时、成功/失败、结束后的活跃数及本次运行峰值 |
| 列表类型 / `remote` | 单个来源整个列表任务的耗时和任务并发；收藏包含所有分页 |

`source` 是身份哈希的短标识，不输出地址、查询词、密码或令牌。列表任务和实际请求分别统计，不能相加当作网络并发。上层等待超时仍不取消底层请求，实际请求的活跃数会持续到该请求结束；真正取消留给后续批次。

这些是加载基线，不是电视帧率测量或性能提升证明。后续在同一设备、同一服务器配置下，对比冷启动/热启动、搜索以及一台来源离线时的日志，再决定调度优化的范围。
