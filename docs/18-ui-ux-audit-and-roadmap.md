# Viora · Windows / Android TV 交互审查与分阶段方案

审查日期：2026-10-15。基线：main `2a02adf`，v0.15.11+35；已 fetch 并确认与 origin/main 一致。
工作分支：`codex/uiux-audit-plan`。审查以此基线为准；后续实施的第一批记录在第10节。

## 1. 判断与边界

现有视觉和组件基础足够继续演进，主要问题是加载范围、焦点与数据更新的衔接、桌面缩放，以及异常和无障碍状态的不完整。建议沿用现有深色品牌，先改善可操作性和浏览连续性，再调整构图与动效。

- 保留 Flutter、Riverpod、go_router；继续使用 Windows mpv、Android TV 默认 ExoPlayer 和既有回退方式。
- 保留媒体源管理、账号隔离、家长控制、缓存完整性规则、片头片尾、弹幕和 TMDB 选集语义。
- 每批只处理一个模块；记录该批功能、性能和输入验证结果，再进入下一批。
- 本文的设计数值和性能门槛是待验证提案，不是已有实测效果，也不代表已经达到商业发布质量。

使用的本地 Skills：UI/UX Pro Max、Motion Design、frontend-design、design-swiftui-interfaces。
SwiftUI Skill 仅用于稳定状态、可取消交互、布局和可访问性的原则参考；Windows / Android TV 的行为按自身平台和现有 Flutter 实现判断。

Skill 检索说明：UI/UX Pro Max 的 `cinematic streaming television --design-system` 返回了营销落地页结构，不能直接套用；随后用 product 域 `video streaming player` 命中 Video Streaming/OTT，只采纳内容主导、深色背景等相关建议。Flutter 检索强调性能测量和共享元素，具体是否采用仍由当前源码与设备结果决定。不会照搬 CSS/GSAP 或替换现有图片组件。Motion Design 中强制三层动效、TV 增长时长等通用建议与本项目低配电视、克制动效目标不符，不采用。

已经实现、应继续保留：

- `FocusRow` 使用横向 `ListView.separated`；电视预构建范围 800、桌面 1600 个设计单位，不是整行无条件构建所有海报。
- 图片共用 `HttpClient`、请求去重和磁盘缓存；电视最多并发下载 4 张，桌面 8 张。
- 电视图片缓存设为 80 MiB / 300 项、背景解码宽度 1280；背景绘制隔离，切换绘制最多保留新旧两层。
- 电视默认 `GlassQuality.low`，不启用实时模糊；页面背景本身使用图片与渐变。
- 焦点背景切换有 350ms（电视）/220ms（桌面）防抖；Hero 预热当前和下一部。
- 左侧栏可通过方向键进出，并恢复内容焦点；鼠标真实移动才抢焦点，避免键盘滚动被静止指针打断。
- 播放器已有自动隐藏、鼠标悬停保护、面板打开保护、音轨/字幕菜单、快进累加、快捷键和分层返回。
- 两种详情页均已支持 TMDB 未播出集数和日期；有超前资源即可播放，不能用日期禁用播放。
- Windows 已有自绘标题栏、拖动/双击最大化、小窗、全屏和连续缩放时的布局冻结。

注意：Flutter `imageCache.maximumSizeBytes` 不是整个进程或所有存活图片的内存硬上限。页面长期持有屏幕外图片仍值得处理，不能只降低这个数值。

## 4. 视觉与布局方向

### 4.1 选择理由

比较两个方向：

- 全屏背景随每次焦点持续改变：电影感强，但信息区跳动、请求频繁、低配混合成本高。
- **固定阅读区 + 焦点停稳后更新背景**：保留现有背景跟随能力，明确区分首页推荐展示与下面的主动浏览；按键反馈立即发生，大图异步更新。

选择后者。独特性来自稳定的左对齐阅读区、Viora 原有冷紫点缀和内容图像，而非新增发光、3D 倾斜、环境粒子或满屏玻璃。

### 4.2 延续现有品牌的令牌提案

| 角色 | 提案 |
| --- | --- |
| 幕布 | `#07080B`，保留现有背景 |
| 面板 | `#14161E`，弱硬件使用实色或高不透明度填充 |
| 主文字/焦点 | `#FFFFFF`，焦点使用清晰轮廓而非只靠阴影 |
| 次文字 | `#C7C9D3`，先验证真实合成背景对比度再替换透明文字 |
| 品牌强调 | `#A9B6FF`，用于选中值/主要状态，保留现有色 |
| 评分 | `#FFD27A`，不与播放主按钮争夺注意力 |

成功/警告/错误沿用现有语义色，并配文字或图标。普通文本以 4.5:1、关键边界与焦点以 3:1 为验证目标；背景有图时验证合成后的实际像素，不能只比两个主题色。

字体继续使用系统中文回退，避免新增在线字体依赖。页面标题、作品标题、行标题、正文、辅助信息分层；Windows 以实际逻辑像素控制可读下限，TV 以观看距离和 720p/1080p/4K 实机验证。数字时间使用等宽数字。

间距收敛到现有 8/16/24/32/48 节奏，沿用卡片 16、面板 24 圆角和胶囊按钮；不将每段信息都包成装饰卡片。

### 4.3 首页构图

```text
┌─导航─┬──────────────────────────────────────────┐
│      │ 背景图 + 固定阅读区                      │
│      │ 作品 Logo / 标题                         │
│      │ 少量元信息、两行简介                      │
│      │ [播放/查看详情]   [收藏（适用时）]          │
│      │                                          │
│      │ 继续观看  [横卡+进度] [横卡] [横卡] →      │
│      │ 推荐行    [海报] [海报] [海报] …           │
└──────┴──────────────────────────────────────────┘
```

- 顶部展示区以“首屏能看到继续观看”为约束，不再只按 72% 高度决定；冷启动、无继续观看和窄窗口分别布局。
- 横排保持作品可辨识的封面比例；先保留已有推荐分类，不在这一批新增复杂的首页导航体系。
- 切入海报浏览后，信息区与背景明确绑定同一作品；慢图继续保留旧图和遮罩，不让播放目标与可读标题错配。
- 加载/刷新不整体清空页面；有缓存即展示，单行失败可重试，空内容、未配置和离线提供不同文案。
- 骨架与最终内容尽量同高；骨架不可接受播放确认，也不能把遥控器焦点困住。

### 4.4 详情构图

```text
背景 + 稳定左侧渐变
标题 / 年份 / 类型 / 评分 / 简介[展开]
[继续 S2E3] [当前资源 · 切换] [收藏] [已看]
季选择：少季横排 / 多季列表
剧集：当前集、已看、未播出和日期分别表达
资源列表 → 媒体信息 → 演职员与相似作品
```

- 两种详情使用相同的操作和加载语言；继续/从头播放、未找到资源、资源查找失败要明确区分。
- **焦点、选中、正在播放**是三个状态；焦点移入某集不等于立即播放，不通过悬停启动视频。
- “未播出”描述日期，“已入库”描述资源；二者可同时存在。保留超前集播放、服务器独有集数和账号切换后的选集重置。
- 简介全文与资源选择用轻量面板，关闭后回到触发控件。返回详情保留季、集和滚动位置。
- 海报过渡只服务于“刚选的作品来到详情”这一关系。默认短淡入，图片未就绪、低配或减少动效时不做共享元素。

### 4.5 播放器构图与状态

顶栏保留标题和低频功能；底栏保留播放/暂停、进度、下一集和高频操作。字幕、音轨、资源、倍速使用一致的菜单尺寸、选中标记和焦点恢复。

控制层明确为隐藏、浏览控件、拖动进度、打开面板等状态；沿用已有行为，先补回归再收敛状态，不在本批修改内核生命周期。

- 播放时无操作自动隐藏；暂停、拖动、菜单打开、TV 控件焦点和鼠标停在控件上时保持显示。
- 隐藏后控件不可点、不可聚焦、不可被辅助技术误读；播放统计、自动跳过和弹幕仍正常运行。
- Windows 拖动显示目标时间，松手一次提交，取消回到实际播放进度；TV 连按左右沿用累加/延后提交，处理返回取消和失焦。
- **缩略图预览分开立项**：先核实 Emby/Jellyfin/其他源的现有图片或 storyboard 能力。有数据才预取小图，无数据回落时间提示；不改数据模型、不抓取整段视频、不启动第二个视频内核。
- 播放错误优先恢复任务：显示可理解的原因、重试/换源/既有内核回退入口。刷新面板不能意外暂停或重新起播。

## 5. 平台输入约定

| 交互 | Windows | Android TV |
| --- | --- | --- |
| 悬停/焦点 | 悬停轻强调；键盘焦点有独立可见轮廓，切换输入不突跳 | 明确高对比焦点，海报建议 1.04–1.06 放大起测，现有 1.08 是否保留由距离与遮挡测试决定 |
| 导航 | Tab/Shift+Tab 到区域，方向键行内移动；保留 Ctrl+F、Alt+←、鼠标侧键 | ↑↓ 跨行、←→ 行内；左边缘进入侧栏，返回内容恢复作品 |
| 焦点记忆 | 返回详情/首页恢复原条目，缩窗后仍可见 | 用稳定行 ID + 作品 ID 记忆；刷新删除条目时回到邻近可用项 |
| 滚轮 | 普通纵向滚动页面；Shift+滚轮/横向触控板滚动海报行，边界不吞掉整页滚动 | 无需鼠标；长按方向键不能跳到隐藏控件 |
| 播放键 | 保留 Space/K、J/L、A/C、F/F11 等；菜单和输入框优先消费自己的按键 | 保留 OK、播放/暂停、媒体快进/快退，控件显示时方向键优先导航 |
| 返回 | 面板→控制层/全屏/小窗→页面，沿用已有分层；标题栏返回与快捷键一致 | 面板→控件→画面→上页；首页不误退，保留长按返回确认退出，避免一次长按连退多层 |
| 窗口 | 自绘标题栏保留；测试拖动、最大化、还原、系统快捷键、多显示器 DPI 和屏幕工作区 | 无标题栏；检查原生视频 SurfaceView 不抢占 UI 焦点 |
| 提示 | Tooltip 展示动作和快捷键；鼠标移走不强制滚动 | 聚焦控件显示简短文字，不依赖悬停或只靠图标猜动作 |

现有焦点记忆保存在挂载行的 State 内。纵向虚拟化后，不能只保留这份 State：应让页面级焦点协调器保留逻辑位置；跨行先滚动使目标行挂载，再请求 FocusNode，并用代次取消旧请求。网络响应或延迟的自动聚焦不得抢回用户已移动的焦点。不要为了焦点记忆把所有海报行永久 keepAlive。

微软键盘指南已核对，可作为 Tab、方向键、可见焦点和输入上下文的参考：
<https://learn.microsoft.com/en-us/windows/apps/develop/input/keyboard-interactions>。
Android TV 焦点指南本次在线读取失败，实施时需核对官方文档与实体设备，不将 tvOS 规则当作 Android 系统行为。

## 6. 动效规范提案

整体取克制的 Premium 方向，但输入反馈使用短时长，不照搬“所有动画 350–600ms”。基础曲线优先 `easeOutCubic`；退出更短，不使用反复弹跳。

| 场景 | 触发与结束 | 常规提案 | 中断/取消 | 减少动效/低配 |
| --- | --- | --- | --- | --- |
| 海报焦点 | 输入即更新描边；新卡稳定后结束 | 缩放 120–150ms；不改变布局尺寸 | 从当前值转向新目标，快速移动只保留当前卡反馈 | 减少动效不缩放，保留即时描边；低配降低阴影成本 |
| 背景 | 焦点停稳且图片可用后更新 | 保留当前防抖起测，交叉淡入约 280–360ms | 仅最后目标生效，旧任务取消或结果丢弃，绘制不叠加多层 | 减少动效直接换图；低配两层以内或直接替换 |
| 内容加载 | 占位变为内容，保持行尺寸 | 100–160ms 淡入 | 不重播整排入场，刷新不移动焦点 | 静态替换；屏外关闭骨架 ticker |
| 面板 | 点击/确认打开，完成/返回关闭 | 进入 180–220ms，退出 120–160ms，小距离位移 | 打开中可返回关闭，不排队播放旧动画 | 无位移、短淡入或直接呈现 |
| 页面 | 从作品进入详情 | 短过渡 180–240ms；共享元素是后续可选项 | 快速返回可打断，恢复触发作品 | 直接呈现，不延后焦点或数据加载 |
| OSD | 输入唤醒、超时隐藏 | 显示 100–140ms，隐藏 140–180ms | 用户再次操作即反向显示，无需等淡出结束 | 直接显示/隐藏；菜单与暂停状态仍生效 |

减少动效和画质档位分别决定行为：高性能电脑也可以选择减少动效；低配 TV 仍保留明确焦点反馈。读取 `MediaQuery.disableAnimations`/系统可访问性信息，并提供应用内选项覆盖或加强；不在每个页面散写时长。所有时长均需目标设备调试后确定。

## 7. 顺序与每批开发边界

### 0：建立可比较基线（诊断模块）

复用现有 `[mem]`、`[jank]`、`[load]` 与局域网导出。开发诊断增加场景、帧预算、build/raster 分布、图片 pending/live、可见行与请求数量；汇总记录，避免逐帧落盘。使用相同媒体源、缓存条件、窗口、设备和路径做前后对照。

交付：操作脚本、带设备信息的基线报告。当前已有 >50ms 的粗粒度卡顿计数仍保留，但不能将 `build+raster` 的简单相加当成屏幕呈现周期，或将 RSS 当成 Dart 堆。

### 1：通用交互组件（不改页面布局）

范围：`VFocusable`、按钮、动效策略与必要语义令牌。统一 hover/focus/pressed/selected/disabled、减少动效、可访问标签和按键取消；保留 TV 行导航和遥控器长短按语义。

验收：鼠标移动后立即改用键盘、短按/长按确认、长按中失焦、禁用操作、快速焦点反转；检查语义角色/状态和减少动效。现有焦点/返回/OSD 测试不得退化。若将其用于全部页面会引起过大差异，先以首页控件验证并收窄变更。

### 2：首页（首个页面模块，优先收益）

2A 只做加载与焦点连续性：纵向虚拟化、相邻行按需订阅、稳定行 ID/作品 ID 的焦点记忆、单行状态、屏外骨架停用。行数据到达前保留槽位或稳定锚点；不让一次 ↓ 跳过尚未就绪的整行。

2B 在 2A 通过后，仍只调整首页：Hero/继续观看首屏比例、标题层级、轮播暂停、背景与信息一致性、桌面横向滚动行为。复用原有图像管线，不为视觉新增海报包或大图生成流程。

2A 的实现、自动化验证范围与待完成的实机验收见 [首页按需构建记录](19-home-lazy-loading.md)。

验收：初始请求不再覆盖全部远端推荐行；下翻时及时预取；按住 ↓、↑ 往返、行尾、侧栏往返、详情返回仍找回原作品；响应乱序、单源离线、无 TMDB、无服务器均能继续操作。图片并发上限、低配材质和缓存账号边界保持。

### 3：详情（两种入口共同升级）

先修多季溢出，再统一首屏状态、简介展开、资源快捷入口、季集选择的选中/焦点表达。继续使用 `DetailLayout` 与 `EpisodeCatalogRow`。共享元素过渡最后评估，可独立省略。

验收：1/30 季、200 集、特别篇、未播出但已入库、日期待定、服务器独有集数、跨服务器同季同集、资源查找失败和账号切换；返回保留位置，不能误播另一集。长中文标题、长字幕和放大字体不挡住播放入口。

### 4：播放器控制层（风险最高，单独一批）

先补状态/输入回归，再做隐藏时的更新隔离、选集面板虚拟化、进度拖动取消、字幕/音轨面板与帮助提示。保留当前 Seek 合并、内核切换和上报机制。OSD 退出动画完成后可移除或静止其 UI 子树，但不得解绑播放时钟及业务订阅。

验收：两个内核各自覆盖起播、续播、连续 seek、换源、换集、内外字幕、音轨、自动跳过、弹幕、缓冲错误、最小化/小窗/全屏和后台恢复；TV OK/媒体键/长按返回、Windows 鼠标与快捷键混合。没有远端预览图片时仍可完整使用进度操作。

### 5：Windows 窗口与适配（单独一批）

先做标题栏键盘可达、焦点视觉与可发现提示，再逐页验证布局密度。由外层真实可用逻辑尺寸决定桌面断点；不在恒为 2240 的内层 MediaQuery 上写永远不触发的断点。按可用尺寸减少列数、改变布局，保持文字和命中区下限；TV 保留大屏布局。

验收：960×540、1280×720、1600×900、超宽和4K窗口；100/150/200% DPI、跨屏、系统放大文本；拖动期间和停止后布局、标题栏、最小化/还原、全屏退出和多屏小窗位置。更改缩放框架前后单独对比性能，不与播放器外观改动混合。

### 后续独立选项

- 继续观看逐来源返回即展示：会触及数据发布过程，单独设计 UI 聚合适配，保持 source snapshot 完整性、账号作用域和成功空列表语义，复用缓存可靠性测试。
- 视频预热取消和前台优先级：单独的预热调度模块，TV 最多一个候选，离开页面/焦点移开/正式播放优先取消候选；增加取消与过期响应测试，不重构播放内核。
- 缩略图预览：完成媒体源能力调查后再决定接入；不能承诺所有来源均有图片。

每个模块独立提交/PR，经验证后合并；只有达到该批发布条件后再按现有流程发版。本次分析分支不改版本号、不触发发布。

## 8. 功能、性能与输入设备的共同验收

### 测量方法

- 设备至少包括低配 Android TV（优先已有 Android 9 电视）、一台较新 TV、Windows 集显设备；记录型号、系统、刷新率、分辨率、DPI、内存及视频内核。
- 使用 profile/release 对目标设备测量；widget test 只能验证行为，不能作为真实帧率和解码性能证据。
- 同一路径冷缓存、热缓存分别至少跑 3 次：打开首页、快速跨行/长按方向、进入详情选季选集、起播、打开关闭面板、退出恢复焦点。固定图片和网络条件，避免把网络波动误判成渲染回归。
- 界面帧记录 build 与 raster 的 P50/P95/P99 和超预算占比；帧预算按实际刷新周期，60Hz 时约16.7ms。视频卡顿另外记录内核/系统可获取的掉帧与缓冲事件，不能从 Flutter 帧数推断视频掉帧。
- 记录首个可操作内容时间、各行请求数量、图片并发/排队、峰值 RSS、图像缓存及10分钟往返浏览后的内存趋势。日志继续用现有局域网入口导出。

### 提议门槛（基线后校准）

| 维度 | 发布条件/目标 |
| --- | --- |
| 功能 | 无新增崩溃、黑屏、误播、进度丢失、账号内容串用；现有核心流程与对应测试通过 |
| 输入 | 遥控器/纯键盘可完成主要任务；焦点始终可见可达；面板关闭回到合理位置；快速重复输入不中断导航 |
| 可访问性 | 减少动效有效；主控件标签与状态可读；关键内容对比度达标；放大文字不遮住主操作；Windows Narrator / 可用时 Android TalkBack 实机检查 |
| UI 性能 | 目标60Hz下努力让构建和栅格化分别落入16.7ms预算；同机同路径 P95、超预算率不出现有统计意义的恶化。首轮可用“中位数恶化超过10%需复查”作为调查阈值，而非拿单次波动判失败 |
| 首页优化收益 | 证明屏外行/图片请求减少、首个可操作内容不变慢；以滚动P95降低约20%作为优化目标，未达到时据实报告瓶颈，不宣称已完成性能目标 |
| 播放稳定性 | UI改动不得增加视频缓冲、掉帧或额外解码器；OSD隐藏时减少自身重建，但跳过、上报、字幕、弹幕保持正确 |
| 内存 | 既有图片并发限制保持；往返浏览内存趋稳，无持续增长；峰值超过同条件基线10%则调查存活图片、预取与面板持有，不靠清空所有缓存掩盖 |

## 9. 建议的第一步

先完成基线记录和通用交互组件的小批验证，再开始首页的“纵向虚拟化 + 焦点恢复 + 分区状态”。它直接针对已确认的额外加载，同时最能验证两平台交互能否在同一品牌下稳定共存。首页通过后再处理详情，播放器放在后面独立验证。

## 10. 第一批实施：通用交互组件

范围是通用控件和接入这些控件的语义参数。首页布局、加载策略、路由、播放时钟、内核与业务数据结构保持现有实现。源设置页的改动只补充开关和图标按钮名称，不改变同步或来源排序逻辑。

### 已实现

- `VFocusable` 统一提供可用/禁用、按钮/开关、选中、焦点、标签和值的语义；辅助技术 tap/longPress 与实际输入使用相同的回调入口。移除导航栏与 OSD 图标按钮重复的语义包装。
- 遥控器/键盘按下确认后，仅对应按键的松开可以提交操作；重复事件不重置长按计时。失焦、禁用、焦点节点更换和销毁都会取消持有的操作，不再延迟弹出旧菜单。
- 鼠标按下提供局部反馈，取消指针或拖动取消时清除反馈；保留右键菜单，以及静止鼠标不抢键盘焦点的既有行为。
- 无回调的按钮不提供激活或菜单动作，使用普通指针和较弱文字；仍可聚焦并显示清晰描边，保留 TV 上“暂无资源”的说明位置及行导航锚点。禁用的排序按钮只降低内容透明度，焦点轮廓不随内容变淡。
- `VMotion` 接入系统 `MediaQuery.disableAnimations`。本批控件在减少动效时不做缩放/焦点光晕，局部颜色变化直接到达目标状态；焦点描边、按下反馈和实际动作仍保留。通用忙碌按钮使用静态进度符号，避免持续旋转。
- 海报、继续观看、人物与平台卡片的可操作区域有明确名称；可视标题不再作为重复的朗读节点。开关、来源排序和季选择分别提供实际名称或选中状态。

减少动效目前只接入本批通用控件。首页轮播、背景、页面过渡与 OSD 整体显隐仍留到各自模块；应用内覆盖开关也未在本批添加。不会据此宣称全应用已完成减少动效适配。

### 验证与后续

新增 `test/focusable_test.dart` 覆盖短按/长按、重复事件、失焦后松键、不同确认键混用、持有期间禁用/销毁、鼠标取消/左右键、语义动作、禁用焦点锚点、减少动效无持续帧、卡片名称、开关/单选与普通操作的语义区别。

- 正式 Dart 3.13.5 + Flutter 3.47.7 框架源码的隔离静态分析通过；兼容 SDK 的相关测试和全量回归通过记录见 PR 验证结果。正式 Flutter 3.47.7 的 CI 在分支 PR 中运行。
- 减少动效测试确认控件稳定后不再持续调度帧；这只验证组件行为，不是实体电视帧率或 GPU 性能数据。
- 还需 Windows 鼠标/键盘/Narrator、Android TV 遥控器与可用的辅助服务进行实机验收；本批不自动合并或发布。
- 实机验收重点：继续观看→详情→播放后返回的焦点不退化；暂无资源按钮可读但不误播；长按确认时移走焦点不弹旧菜单；减少动效下仍能明确辨认当前控件。
