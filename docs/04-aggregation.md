# 04 · 聚合索引、聚合搜索与多资源选择

## 1. 为什么需要本地聚合索引

- 首页推荐来自 TMDB，点进去要立刻知道"哪些服务器有这部"。逐台实时搜索太慢（10+ 台服务器、部分在海外）。
- 同一部作品在多台服务器上各有一份甚至多份，需要合并成一个"作品"，再在详情页列出所有版本。

因此每台服务器的**电影和剧（不含单集）**同步到本地 `index_items` 表。按截图里的量级（单台 3 万电影 + 1.7 万剧），单条记录约 300 字节，十几台服务器也就几十 MB，可接受。

## 2. 同步策略

| 时机 | 动作 |
| --- | --- |
| 添加服务器 | 全量同步（分页 500 条，后台进行，资源库卡片显示进度） |
| App 启动 / 每 6 小时 | 增量同步（Emby `MinDateLastSaved`，Plex `updatedAt>`，Jellyfin 按 `DateLastSaved` 倒序翻页直到遇到已知时间点） |
| 每 7 天 | 全量校对一次，清理服务器上已删除的条目 |
| 详情页打开时 | 对已命中的服务器做一次实时校验，条目不存在则从索引删除 |

同步只取必要字段：`Id / Type / Name / OriginalTitle / ProductionYear / ProviderIds / ImageTags / DateCreated`。

## 3. 作品匹配（合并规则）

按优先级依次尝试，命中即合并：

1. `tmdb_id`（同时比对 kind，电影和剧的 TMDB ID 空间不同）
2. `imdb_id`
3. `tvdb_id`（剧集）
4. 兜底：`title_norm + year`（±1 年容差）+ kind 一致

`title_norm`：全角转半角、繁转简、去标点与空白、去"第X季""(2021)"等后缀、小写。

不同服务器的条目若只有兜底匹配命中，在详情页"播放资源"里标注"按标题匹配"，用户可手动"不是这部"拆开（写入本地 `match_override` 表）。

## 4. 聚合搜索

```
输入关键字（防抖 400ms）
 ├─ ① 本地索引 LIKE / FTS5 查询           → 立即出结果（<50ms）
 ├─ ② TMDB /search/multi                    → 补充"媒体库没有"的结果、人物
 └─ ③ 各服务器实时 Search（并发，单台 4s 超时）→ 补齐索引未同步到的新内容
合并：按 §3 规则去重 → 排序
```

排序：有资源的优先 → 精确标题匹配 → TMDB 热度 → 年份新的优先。

结果分区展示：

| 分区 | 内容 |
| --- | --- |
| 电影 / 剧集 | 聚合后的作品卡片，角标显示"3 个资源"或"无资源" |
| 单集 | 服务器实时搜索命中的集（例如搜集标题） |
| 人物 | TMDB 人物，点进去看作品并标出可播放的作品 |

TV 端搜索输入：屏幕键盘（拼音首字母 + 全拼两种布局）、语音输入（Android TV 系统语音 `RecognizerIntent`）、热门搜索与历史。

## 5. 多资源（多版本）选择

### 5.1 资源解析

详情页选中某一集 / 某部电影后，`ResolveSources`：

1. 从聚合作品拿到所有 `copies`（每台服务器上的条目）。
2. 剧集：在每台服务器上按 `seasonNumber + episodeNumber` 找到对应集（缓存该剧的季集列表）。
3. 并发调用 `playbackInfo()`，每台 5s 超时，先回来的先显示（面板渐进出现，不等最慢的服务器）。
4. 每个 `MediaSource` 生成一张版本卡片。

### 5.2 分组与标签（对应 Rex 截图"播放资源：4K / 1080P / 其他"）

| 分组 | 条件 |
| --- | --- |
| 4K | 宽 ≥ 3200 或 高 ≥ 1800 |
| 1080P | 宽 ≥ 1800 或 高 ≥ 1000 |
| 其他 | 其余（720P、SD、未知） |

卡片内容：

```
┌───────────────────────────┐
│ HDR 10            ✓（已选） │   动态范围：DV / HDR10+ / HDR10 / HLG / SDR
│ 494.4 MB   2.66 Mbps       │   大小、码率
│ HEVC · 10bit · 24fps · 5.1 │   编码、位深、帧率、主音轨声道
│ [图标] ChaPanda · 主线路    │   服务器 + 当前线路
└───────────────────────────┘
```

聚焦卡片后可展开"媒体信息"（视频 / 音频 / 字幕三栏，对应截图下方的详细参数和"入库时间"）。

### 5.3 默认选中规则

可在设置中调整，默认：

1. 用户上次在该剧选择的服务器（同一部剧连续观看时不跳服务器）
2. 设备能力匹配：设备不支持 HDR → 降低 HDR 版本权重；不支持 DV 且版本为 DV Profile 5 → 降权（mpv 能做色彩映射，ExoPlayer 不能）
3. 分辨率偏好（默认"最高"，可选"1080P 优先"以节省流量）
4. 线路延迟低者优先
5. 码率高者优先

### 5.4 播放中切换

播放器侧边面板"资源"页列出同一集的全部版本，切换时保持当前进度（见 08）。某个版本起播失败（网络错误、403、解码失败）时，自动提示"切换到下一个资源？"并倒计时 5 秒自动切换。

## 6. 实现说明（v0.4.0）

| 模块 | 文件 |
|---|---|
| 标题归一化 / 拼音 | `lib/data/index/title_norm.dart`（全角转半角、繁转简、去年份 / 季号 / 标点；`lpinyin` 生成首字母与全拼） |
| 索引存储 | `lib/data/index/media_index.dart`（`sqlite3`，`items` + `sync_state` 两张表；全量同步用代号 `gen` 删除服务器上已不存在的条目） |
| 同步调度 | `lib/data/index/index_sync.dart`（启动 2 秒后同步全部服务器；每页 500 条；距上次全量超过 7 天走全量，否则按 `MinDateLastSaved = 上次增量 − 5 分钟` 增量） |
| 多资源 | `lib/data/aggregate/sources.dart`（单集按"剧集副本 + 季号 + 集号"跨服务器映射；各服务器 `PlaybackInfo` 并发、单台 8 秒超时；排序：偏好服务器 → 分辨率 → 延迟（差 > 80ms 才算）→ 码率） |
| 聚合搜索 | `lib/features/search/search_page.dart`（本地索引先出结果，再并发实时搜索各服务器、单台 5 秒超时，回来一台合并一台） |

Web 预览构建不支持 SQLite（条件导入 `sqlite_stub.dart`），此时只走服务器实时搜索。

### 6.1 减轻媒体服务器负载（v0.8.1）

- 客户端只在登录、线路、代理、UA 变化时重建（`AppConfig.clientKey`）；测速延迟、片量、访问时间写回配置不再触发各列表重新请求。
- 索引同步用精简字段（不含 UserData / RecursiveItemCount / ChildCount），每页 200 条、页间隔 400ms，启动后延迟约 9 秒开始。
- 列表请求去掉 `RecursiveItemCount`、`PrimaryImageAspectRatio`（Emby 需逐条递归统计 / 读取图片尺寸）。
- 详情页列资源与预加载用 `IsPlayback=false` 查询播放信息。
- 图片：请求尺寸固定为 240 / 360 / 480 / 720 / 1080 / 1440 / 1920 / 2560 / 3840 几档（Emby 每个新尺寸都要现场缩放），并缓存到本地磁盘（上限 512MB），再次打开不再向服务器请求。

## 7. 什么时候搜索资源

- **首页、推荐行只做展示**：TMDB 推荐（Hero、海报行）不查媒体库；最近入库也不显示跨服务器的资源数，首页任何地方都不显示"N 个资源 / 无资源"。
  Windows 点封面大图进详情（没有「查看详情」按钮）；电视保留「查看详情」按钮供遥控器聚焦。
- **进入 TMDB 详情页才聚合搜索**（`tmdbLibrarySearchProvider`）：本地索引 + 到每台服务器按中文名 / 原名实时搜索
  （每台每个关键词 1 次请求、8 秒超时），按 TMDB ID 匹配，没有 ID 时按标题 + 年份 ±1。
  找到后显示「播放 / 去选集观看」和「选择资源」，没找到显示「用关键词搜索」。
- 媒体库详情页的"播放资源"仍按聚合索引跨服务器匹配（§3）。启动后的后台索引同步（全量 7 天一次，平时增量）不变。
