# 首页 2A：按需构建与焦点连续性

日期：2026-10-15。分支：`codex/home-lazy-navigation`，基于通用交互组件批次 `1c0b537`（PR #27）。范围对应 [交互路线图](18-ui-ux-audit-and-roadmap.md) 的 2A。

以下为 0.15.12 发布时的记录；快速下翻加载过晚的后续修正见本文末尾。

## 行为变化

- 纵向列表只构建视口及前后 160 逻辑像素范围内的行。推荐与人物的订阅放在各自行内，接近时才发起；Hero 的今日趋势仍在首屏订阅。
- 页面保留逻辑行顺序和每行最后聚焦的作品 ID。离屏行可以销毁；再次进入时先挂载行及目标卡片，再请求焦点。作品插入后仍跟随同一 ID，删除后回到邻近位置。
- 只让正在持有焦点的行保活。长按可以经过未挂载的行；快速反向、鼠标操作、转入侧栏或离开页面会使旧的异步聚焦失效。
- 加载中的行保留不可激活的焦点锚点；数据到达时留在当前行，用户已离开时不抢焦点。继续观看行消失后进入下一行。
- 未配置、加载中、成功空列表、失败分别显示。推荐/人物请求不再将错误转换为空列表；重试只刷新当前行，保留其他内容。
- TV 骨架为静态，屏外行停用 ticker；减少动画时滚动直接定位，保留清晰焦点。

横排稳定键和按需节点接口沿用 `FocusRow`，其他页面继续使用默认行导航。没有新增图像库、全屏模糊、播放内核或业务模型；图片缓存和并发限制沿用现有实现。

## 验证与实际收益的边界

1920×1080、无服务器、每个 TMDB 推荐行 30 个作品的固定测试中：初始推荐 provider 启动从审查基线的 6 个变为 2 个（今日趋势及邻近的正在热映），人物 provider 尚未启动，挂载的海报卡少于 20 个。这里统计的是 provider 启动和 widget 挂载，不能视为实际 HTTP 请求数、解码图片数、内存或帧率测试。

新增 12 项回归覆盖按需订阅、长按跨行、横向远端卡片、行回收后的记忆、占位替换、迟到响应、局部重试、作品增删、侧栏混合输入、详情返回、快速反向、减少动画及继续观看行移除。另回归原有焦点、TV 返回、未来剧集和跨服务器播放等用例。

本地以 Dart 3.13.5 配合 Flutter 3.47.7 框架源码静态分析，无问题；运行测试使用隔离的 Flutter 3.44 兼容副本，236 项通过、12 项外部服务测试按既有规则跳过，不修改正式依赖。正式 Flutter 3.47.7 的分析与全量测试由本批 PR 的 Checks 验证，以其结果为准。

## 实机验收

尚未连接 Windows 或 Android TV，本批不能据此承诺 60fps。复用现有局域网日志访问与导出，不增加日志获取入口。对照前一批，在相同账号、缓存条件、分辨率下检查：

1. 冷启动和热启动首页；下翻到人物及高分剧集再返回，确认有内容前有稳定占位。
2. 遥控器长按上下、立即反向、行内长按到远端，再往返侧栏及详情；确认恢复同一作品。
3. 一行断网后重试、慢请求迟到、播放完成导致继续观看消失，确认不会抢焦点或自动播放。
4. Windows 鼠标滚动后立即切换键盘、窗口缩放、大字体、系统减少动画；TV 检查焦点轮廓和静态骨架。
5. 导出相同路径的 `[jank]`、`[mem]`、`[load]` 记录作对照；既有粗粒度卡顿日志不足以计算 P95/P99 或稳定帧率。

后续首页 2B 再处理 Hero/继续观看首屏比例、轮播暂停、背景与信息一致性及桌面横向滚轮，不混入本批。

## 修正：列表请求与卡片挂载分开

0.15.12 发布后收到快速下翻时多个模块显示过慢的反馈。源码确认：160 设计像素的卡片预构建范围同时决定列表接口何时启动；尚未准备数据的行接近屏幕后，必须先等 JSON，再开始海报下载。此前只统计初始 provider 数量，没有覆盖有延迟的接口下连续浏览的等待，预取时机过于保守。

修正保留虚拟列表与焦点记忆，将轻量列表数据提前放进独立队列，最多同时执行两个后台任务，前方行优先。可见行仍直接读取同一 provider，不用等待后台队列空闲，也不会重复请求同一份数据。首屏停留时也会陆续准备剩余列表，这是减少下翻等待的流量取舍；不再以“总共只启动两个 provider”为验收目标。

图片只预取下一未挂载行首屏、最多 8 张，每次额外预取一张，与实际卡片使用相同 URL、解码尺寸和缓存。滚动改变目标后替换尚未开始的图片任务，保留已有下载并发与 TV 图片缓存上限，不为了预取挂载整排卡片或请求全屏背景、完整详情。进入详情后暂停排队任务，返回首页继续；页面销毁或 TMDB 客户端改变时丢弃旧队列。

验证新增慢接口完成后再下翻、两个慢预取不阻塞远端可见行、屏外首屏海报准备、详情往返暂停/恢复，以及队列并发、去重、变向、失败和销毁等回归。原有离屏焦点记忆、长按与减少动画用例继续保留。实机网络耗时和帧率仍需相同电视、缓存条件下对照，不保证未完成请求的行能够瞬时显示。

本地 Dart 3.13.5 配合 Flutter 3.47.7 框架源码分析无问题；隔离 Flutter 3.44 兼容副本全量 244 项通过、12 项外部服务测试跳过。正式 Flutter 3.47.7 的结果以修复 PR 的 Checks 为准。
